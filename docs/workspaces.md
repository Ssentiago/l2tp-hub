# Workspaces (пространства) — переработка модели данных

## Контекст / зачем

Текущая модель: единый плоский пул `connections` + `labels` на всё приложение.
Реальный кейс юзера: два логически разных контекста — "Личное" (1 домашний
роутер) и "Клиенты ITEGO" (десятки клиентских подключений с группировкой по
Компания/Филиал). Сейчас они смешаны в один список.

Решение: ввести Workspace как контейнер, между которыми можно переключаться.
Внутри каждого Workspace — свой список connections и своя настройка group_by.

## Принципиальное решение: что общее, а что изолированное

- **Labels — общие** на всё приложение, видны во всех workspace
- **Connections — изолированы**, принадлежат конкретному workspace
- **group_by — изолирован**, свой на каждый workspace

## КРИТИЧНО: это должно быть явным для пользователя в UI

1. В разделе управления labels — подпись: "Метки общие для всех пространств.
   Подключения и группировка — свои в каждом пространстве."
2. При создании нового label — подсказка: "Будет доступна во всех пространствах."
3. При первом созданном втором workspace — одноразовый short-tip:
   "Подключения и группировка теперь раздельные для каждого пространства.
   Метки остаются общими."

## Модель данных

```rust
pub struct Workspace {
    pub id: String,
    pub name: String,           // "Личное", "Клиенты ITEGO"
    pub connections: Vec<Connection>,
    pub group_by: Vec<String>,  // ordered label IDs
}

pub struct Store {
    pub workspaces: Vec<Workspace>,
    pub active_workspace_id: String,
    pub labels: Vec<Label>,     // ОБЩИЕ
}
```

## Миграция

Текущие `connections` оборачиваются в один Workspace с дефолтным именем
("Основной"). Без модалки — просто автоматически. group_by = ["company", "branch"].
Юзер переименует при необходимости.

## Трей — ВСЕ workspace секциями

Трей показывает connections из ВСЕХ workspace, сгруппированные по workspace:

```
── Личное ──
  Домашний (192.168.1.1)
── Клиенты ITEGO ──
  Gymnasium
    Крылатское, Лапино, Рига...
  Металлект
    Офис
  НИЦ Энерго
    Офис
```

Если group_by пустой — плоский список без подгрупп.
Активный workspace визуально выделен (bold/чекмарка у заголовка).

## UI: переключение между workspace

- Селектор/вкладки в верхней части окна (рядом с поиском)
- Кнопка создания нового workspace
- Переименование / удаление (с подтверждением: "Будут удалены N подключений")
- При удалении labels — запретить если используется в connections

## Сохранение

- Переключение workspace — тихий save без индикации
- Мутации connections — как сейчас, просто адресуется в активный workspace
- Изменение group_by — обычный save

## Порядок реализации

1. Модель данных: Workspace + миграция
2. Backend команды: CRUD workspace, адаптация commands под активный workspace
3. UI: переключатель workspace + создание/удаление/переименование
4. UI: подсказки про "labels общие"
5. N-уровневая группировка внутри Workspace
6. Tray: все workspace секциями
7. Тестирование миграции
