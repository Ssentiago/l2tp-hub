# Ядро l2tp-hub-core

Документ описывает устройство крейта `l2tp-hub-core`, его модули и контракты. Ядро
не зависит от Tauri и переиспользуется приложением и потенциально консольными
инструментами.

## Назначение

Ядро инкапсулирует всё, что не связано с GUI: модели данных, доступ к базе, работу со
связкой ключей, генерацию конфигов, управление демонами, маршрутизацию и статус
туннеля. Tauri-слой вызывает функции ядра и пробрасывает результат во фронт.

## Публичные модули

Модули экспортируются через `lib.rs`: `db`, `env`, `executor`, `guardian`, `keychain`,
`l2tp`, `models`, `store`, `store_actor`, `utils`. Также реэкспортируются `AppEnv`,
`PrivilegedExecutor`, модели и `Store`.

### env

Глобальное окружение приложения `AppEnv`. Поля: `app_data_dir` (директория данных),
`db_path` (путь к базе), `resource_dir` (bundled ресурсы). Инициализируется один раз
через `init_env`, читается через `global_env`. Методы `config_dir` и
`session_logs_dir` возвращают рабочие пути.

Важно: `AppEnv` это глобальный `OnceLock`. Повторная инициализация паникует. Многие
функции ядра не работают без предварительного `init_env`.

### executor

Трак `PrivilegedExecutor` с методом `run(&self, args) -> Result<String, String>`.
Это абстракция запуска команд с root-привилегиями. GUI реализует её через helper
(класс `SudoSession` в `src-tauri`), консольный инструмент может реализовать через
sudo напрямую. Ядро никогда не выполняет root-команды само, только через этот трак.

### models

Структуры данных: `Connection`, `ConnectionPayload`, `Label`, `Workspace`. Подробно
описаны в `data-model.md`.

### store

Загрузка и сохранение корневого состояния. `Store` содержит рабочие пространства,
активное пространство и метки. Функции `load` и `save` асинхронные, работают через
`db`. При пустом состоянии создаётся дефолтный Store с пространством "Основной" и
встроенными метками.

### store_actor

Актор состояния: сериализует все мутации Store через почтовый ящик (mpsc и
oneshot). Команды передают замыкание `FnOnce(&mut Store)`, актор выполняет
загрузку, мутацию, сохранение различий и коммит в одной транзакции, затем
возвращает пост-состояние вызывающему. Так параллельные команды не затирают
правки друг друга. `StoreHandle::clone` дешёвый, `StoreHandle::load` читает
снимок напрямую из пула и через почтовый ящик не проходит.

### db

Доступ к SQLite: инициализация пула, создание таблиц, загрузка и сохранение Store,
миграция из JSON, выборки по рабочим пространствам. Схема описана в `data-model.md`.

### keychain

Работа с системной связкой ключей через крейт `keyring`. Разделена по платформам
(`macos.rs`, `windows.rs`). Сервис `com.sentiago.l2tp-hub`, имена ключей
`password_{id}` и `shared_{id}`.

### utils

`service_hash` вычисляет хеш конфигурации сервиса из сервера, пользователя, имени
сервиса, пароля и общего ключа. Используется для определения, нужно ли пересоздавать
конфиги VPN.

### guardian

Клиент unix-сокета route-guardian. Публичные функции: `heartbeat`, `set_state`,
`clear_state`, `cleanup`, `status`, `is_guardian_running`. Структура ответа
`GuardianResponse`. На Windows функции возвращают заглушки, guardian работает только
на macOS.

## Модуль l2tp

Главный модуль ядра. Реэкспортирует платформенную реализацию: `macos` на macOS,
`windows` на Windows. Вызывающий код пишется без привязки к платформе.

### macOS реализация

Разбита на подмодули в `l2tp/macos`:

| Модуль | Назначение |
|--------|-----------|
| `config.rs` | Генерация конфигов swanctl, xl2tpd, pppd, strongswan |
| `connect.rs` | Логика подключения, отключения, переключения режима |
| `manager.rs` | `L2tpManager`, мульти-подключения, статусы |
| `routes.rs` | Захват и восстановление маршрутов, состояние на диске |
| `daemon.rs` | Генерация plist, установка и запуск LaunchDaemon |
| `guardian.rs` | Установка guardian, heartbeat, шлюз по умолчанию |
| `cleanup.rs` | Полная очистка VPN-состояния |
| `helpers.rs` | Проверки процессов, PPP-интерфейсы, логирование |
| `paths.rs` | Константы путей, имена демонов, sanitize |
| `error.rs` | `ConnData`, `ConnectError`, классификация ошибок |

Ключевые публичные функции: `create_vpn_service`, `delete_vpn_service`, `connect_vpn`,
`disconnect_vpn`, `disconnect_single`, `switch_tunnel_mode`, `get_vpn_status`,
`list_vpn_services`, `configs_exist`, `cleanup_all_vpn_state`, `check_ipsec_sa_alive`,
`capture_physical_route`, `get_default_gateway`.

Реэкспорты собраны в `l2tp/macos/mod.rs` для обратной совместимости: внешний код
использует `crate::l2tp::*`.

### Windows реализация

Находится в `l2tp/windows.rs` и `l2tp/windows/manager.rs`. Упрощённая: без
LaunchDaemon, без guardian, без split tunneling. Привилегированный запуск идёт
напрямую.

## ConnData и мульти-подключения

Структура `ConnData` несёт данные одного подключения для генерации конфигов:
идентификатор, имя сервиса, сервер, пользователя, пароль, общий ключ, режим туннеля,
подсети. При мульти-подключении собирается список `ConnData` для всех активных
подключений и генерируется единый merged конфиг.

`L2tpManager` в `manager.rs` держит множество активных подключений и реализует
правила: full-туннель эксклюзивен, split-туннели параллельны если подсети не
пересекаются. Подробно жизненный цикл описан в `vpn-lifecycle.md`.

## Классификация ошибок

`ConnectError` в `error.rs` различает: `ServerUnreachable`, `AuthenticationFailed`,
`NoProposalChosen`, `PppAuthFailed`, `Unknown`. Функция
`classify_connect_failure` парсит логи charon и pppd и выбирает категорию, из которой
формируется понятное пользователю сообщение (`user_message`).

## Договорённости ядра

Асинхронность. Функции, работающие с базой, асинхронные. `L2tpManager::connect` и
`disconnect` асинхронные, потому что используют `tokio::sync::Notify` для
синхронизации PPP-интерфейсов. Вызывающий код обязан учитывать это.

Привилегии. Любые root-операции идут через `&dyn PrivilegedExecutor`. Прямые вызовы
sudo не добавляются.

Глобальное состояние. Часть функций зависит от инициализированного `AppEnv`. До работы
с ядром вызывается `init_env`.

Восстановление мьютексов. Используется
`lock().unwrap_or_else(|poisoned| poisoned.into_inner())` чтобы пережить poisoning.
