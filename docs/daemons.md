# Привилегированные демоны

Документ описывает два постоянных демона с root-правами: helper и route-guardian.
Оба устанавливаются как LaunchDaemon'ы и общаются с приложением через unix-сокеты.

## Общая роль

Приложение работает без root-прав, но для управления VPN нужны привилегии. Для этого
используются два демона, запускаемые от root через launchd. Helper выполняет команды,
guardian страхует систему от остатков VPN при падении приложения.

## Helper (l2tp-hub-helper)

Исходники: `helper/src/main.rs`, `helper/src/allowlist.rs`, `helper/src/peercred.rs`.
Пакет `l2tp-hub-helper`, версия 0.8.0. Зависимости: serde, serde_json, libc.

### Запуск и сокет

Демон удаляет устаревший сокет и слушает `/var/run/l2tp-hub-helper.sock`. Сокет
создаётся с правами 0660 и владельцем root:admin (на время bind выставляется umask
077, чтобы сокет не появился с широкими правами даже на мгновение). Если выставить
права или владельца не удалось, демон завершается: работать с открытым сокетом он не
согласен. Работает в цикле, обрабатывая по одному подключению: проверяет пира,
читает строку, выполняет команду, пишет JSON-ответ.

LaunchDaemon plist: метка `com.sentiago.l2tp-hub.helper`, `RunAtLoad` и `KeepAlive`
включены (launchd перезапускает при падении), логи в `/tmp/l2tp-hub-helper-stdout.log`
и `/tmp/l2tp-hub-helper-stderr.log`. Запускается от root, ключ `UserName` отсутствует.

### Протокол

Запрос: одна строка с JSON-массивом argv, например `["cp", "src", "dst"]`.
Ответ: одна строка `{"ok": bool, "stdout": string, "stderr": string}`.

Клиентская сторона: `src-tauri/src/helper.rs`, функция `send_command`. Таймаут чтения
30 секунд.

### Проверка подключившегося

До чтения запроса демон узнаёт uid пира через `getpeereid`. Разрешены root и
консольный пользователь (владелец `/dev/console`): приложение работает под
залогиненным пользователем, остальные логины системы выполнение команд не получают.
Отклонённое подключение получает `{"ok": false, "stderr": "peer not allowed"}`.
`getsockopt LOCAL_PEERCRED` не используется: на современных macOS он возвращает
пустой `xucred`, заполняя только `cr_version`.

### Команды

Все команды до запуска проходят allowlist (`helper/src/allowlist.rs`): сверяются имя
бинарника, форма аргументов и префиксы путей. Вне разрешённых форм ответ
`{"ok": false, "stderr": "command rejected: ..."}`, процесс не запускается.

`version`. Возвращает версию helper из `CARGO_PKG_VERSION`. Используется для
рукопожатия версий.

`guardian_start`. Отдельная ветка `start_guardian`. Запускает бинарник guardian
полностью отсоединённо (stdin, stdout, stderr в null, без ожидания). Разрешён только
`/Library/PrivilegedHelperTools/l2tp-hub-guardian`, другой путь отклоняется. В
текущем коде этот путь почти не используется, guardian ставится иначе.

Остальные команды. Разрешены только формы, которые шлёт `l2tp-hub-core`: `cp`,
`chmod`, `chown`, `mkdir`, `rm`, `cat`, `route`, `ifconfig`, `pkill`, `env` для
swanctl, `launchctl`, `true` и `bash -c` с фиксированными сниппетами. Пути
проверяются по префиксам (например `/private/var/root/l2tp-hub`, `/var/run`,
`/etc/ppp`, `/Library/LaunchDaemons`), абсолютные, без `..`. `bash` принимает только
четыре точные строки-сниппета из connect.rs, любой другой shell-код отклоняется.
Выполняется от root через `exec_with_timeout`: запуск процесса с переданным argv,
опрос завершения каждые 100 мс, убийство по таймауту 25 секунд. Возвращаются код
завершения, stdout и stderr.

Важно: allowlist повторяет формы команд из `l2tp-hub-core`. При изменении вызовов в
ядре (новые пути, новые флаги, другие строки `bash -c`) их нужно синхронно добавить в
`helper/src/allowlist.rs`, иначе helper начнёт отклонять собственные команды
приложения.

### Установка и версия

`sudo.rs` в `src-tauri` управляет установкой helper. При несовпадении версии helper
переустанавливается: `launchctl bootout`, затем `install_helper` через `osascript` с
правами администратора (копирование бинаря в `/Library/PrivilegedHelperTools` с
правами 544 и plist в `/Library/LaunchDaemons` с правами 644, затем bootstrap и
kickstart).

Рассинхрон версий: helper сейчас 0.8.0, приложение ждёт 1.0.0. Подробности и риски
описаны в `AGENTS.md`.

### Модель безопасности

Сокет доступен только root и группе admin, каждый коннект проверяется по uid пира,
команды идут через allowlist с валидацией аргументов. Остаточный риск: любой процесс
консольного пользователя может вызывать разрешённые команды (route, pkill и так
далее), то есть управлять VPN-состоянием машины. Полное закрытие потребовало бы
проверки code signature подключающегося приложения, это не реализовано. Учтено при
любых изменениях безопасности.

Сокет route-guardian (`/tmp/l2tp-hub-guardian.sock`) по-прежнему слушает в режиме
0777 без проверки пира: это отдельная дыра, в задачу по helper не входила.

## Route guardian (l2tp-hub-guardian)

Исходники: `route-guardian/src/main.rs`. Пакет `l2tp-hub-guardian`, версия 0.8.0.
Зависимости: serde, serde_json, libc.

### Назначение

Постоянный демон, который следит за VPN и физической сетью. Если приложение падает или
VPN умирает, guardian возвращает системе рабочие маршруты и убивает остатки процессов.
Это страховка от ситуации, когда default route остался указывать на мёртвый PPP-интерфейс
и машина теряет доступ в интернет.

### Пути и тайминги

Сокет: `/tmp/l2tp-hub-guardian.sock` (права 0777, неблокирующий accept). Файл
восстановления состояния: `/private/var/root/l2tp-hub/route.state`. PID приложения:
`/tmp/l2tp/tauri.pid`. PID guardian: `/tmp/l2tp/route-guardian.pid`. Карта сети:
`/tmp/l2tp/network-map.json`.

Таймаут heartbeat: 12 секунд. Шаг основного цикла: 3 секунды. Обновление карты сети:
каждые 5 секунд.

### Протокол

Запрос: строка JSON `{"cmd": "...", "server", "iface", "gateway", "tunnel_mode",
"split_routes"}`. Ответ: строка JSON `{"ok": bool, "error", "mode", "vpn_alive",
"pppd", "charon", "xl2tpd", "network_map"}`.

Команды: `set_state` (активировать мониторинг, сохранить состояние маршрутов),
`clear_state` (деактивировать, удалить состояние), `heartbeat` (сброс таймера и проверка
процессов), `cleanup` (полная очистка), `status` (состояние и карта сети), `map`
(только карта сети). Клиентская сторона: `l2tp-hub-core/src/guardian.rs`.

### Машина состояний

Guardian работает в двух режимах: Idle и Active.

Idle. Только картография сети каждые 5 секунд и обслуживание команд. Начальное состояние.

Active. Полный мониторинг. Переход в Active по команде `set_state`, обратно в Idle по
`clear_state`, `cleanup`, аномалии или таймауту heartbeat. Демон при этом не
завершается, он живёт постоянно.

### Heartbeat и таймауты

В режиме Active каждый шаг (3 секунды) проверяется следующее:

Аномалии. Если default route указывает на PPP, utun или ipsec интерфейс, а процесс pppd
мёртв, это аномалия: выполняется полная очистка и переход в Idle.

Таймаут heartbeat. Если прошло больше 12 секунд без команд, проверяется PID приложения
через `/tmp/l2tp/tauri.pid` и `kill(pid, 0)`. Мёртвый PID означает очистку и переход в
Idle.

Ghost heartbeat. Если прошло больше 36 секунд (тройной таймаут), очистка выполняется
независимо от состояния PID приложения.

Приложение шлёт heartbeat каждые 3 секунды из heartbeat-потока (`l2tp/macos/guardian.rs`),
поэтому здоровое приложение укладывается в окно 12 секунд с большим запасом.

### Полная очистка

`full_cleanup` выполняет по порядку: удаление хост-маршрута до сервера, восстановление
default route (для split только удаление подсетей), убийство процессов pppd, xl2tpd,
charon (SIGTERM, затем через 2 секунды SIGKILL), остановка и удаление LaunchDaemon'ов
charon и xl2tpd, удаление control и pid файлов, удаление `route.state` и root-директории
активных конфигов с секретами, удаление PID приложения.

Восстановление шлюза в guardian трёхуровневое, как и в ядре: исходный интерфейс если
активен, сохранённый шлюз если достижим, любой активный физический интерфейс.

### Картография сети

`update_network_map` каждые 5 секунд сканирует интерфейсы `en0` через `en9`, `bridge0`,
`awdl0`, `llw0` через `ifconfig`, определяет активность и IP, находит шлюз для каждого
интерфейса, читает текущий default route и записывает физический интерфейс и шлюз
(когда default route не выглядит как VPN). Вся карта пишется в
`/tmp/l2tp/network-map.json`. При выходе демон убирает сокет, PID-файл и карту.

### Установка

`install_guardian_daemon` в `l2tp/macos/guardian.rs`: копирование бинаря в
`/Library/PrivilegedHelperTools/l2tp-hub-guardian` (права 555, владелец root:wheel),
plist в `/Library/LaunchDaemons`, затем `launchctl bootout` и `bootstrap`. Всё
выполняется через helper.

### Устаревший скрипт

`src-tauri/resources/route-guardian.sh` это bash-аналог guardian в виде отсоединённого
скрипта-сторожа. Он вытеснен демоном `route-guardian` и в текущем коде не используется,
не входит в бандл и рабочей точкой входа не является.
