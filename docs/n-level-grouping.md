# N-уровневая группировка подключений

## Проблема

Группировка жёстко привязана к двум полям: `company` → `branch`. Все подключения обязаны вписываться в эту модель. Домашний роутер с "Дом/Дом" выглядит нелепо.

## Решение

Пользователь выбирает **упорядоченный список** labels как оси группировки. Порядок определяет глубину вложенности.

- `[]` → плоский список
- `["company"]` → одна группировка
- `["company", "branch"]` → два уровня (как сейчас)
- `["branch", "company"]` → инверсия

### Уточнения

**`priority` не используется.** Legacy поле, сортировка не по нему. Сортировка групп — алфавит (`localeCompare`). Внутри группы — как есть.

**Пустое значение label = схлопывание уровня, НЕ "Без значения".** Если у connection нет значения для текущего уровня группировки (`c.labels[field]` отсутствует/undefined):

- НЕ создаётся группа с заголовком "Без Филиала" / пустая строка
- Запись рендерится напрямую в родительской группе, минуя текущий уровень
- Пустых заголовков групп в UI быть не должно

Пример. `group_by = ["company", "branch"]`. У "Домашнего" заполнено только `company = "Дом"`, `branch` пустой.

Должно получиться:
```
Дом
  Домашний (192.168.1.1)
```

НЕ должно:
```
Дом
  Без Филиала
    Домашний (192.168.1.1)
```

Логика: записи без значения для `field` собираются в "unlabeled" и добавляются в результат рекурсии напрямую (как плоские items), минуя GroupNode. Конкатенация: [сгруппированные] + [негруппированные]. Это касается каждого уровня рекурсии.

## Примеры UX

### Настройки (Settings)

Секция "Группировка":

```
┌─────────────────────────────────────────┐
│  ГРУППИРОВКА                            │
│                                         │
│  Порядок меток для группировки          │
│  списков. Пусто = плоский список.       │
│                                         │
│  ┌─────────────────────────────┐        │
│  │ ≡ Компания            ✕    │        │
│  ├─────────────────────────────┤        │
│  │ ≡ Филиал              ✕    │        │
│  └─────────────────────────────┘        │
│                                         │
│  [+ Добавить метку          ▼]          │
│                                         │
│  Пример: Компания → Филиал              │
│  "НИЦ Энерго" → "Офис"                 │
└─────────────────────────────────────────┘
```

- **≡** — drag handle (порядок = глубина)
- **✕** — убрать из группировки
- **[+ Добавить метку]** — dropdown с доступными labels
- Под списком — preview текущей группировки

### Результат в списке подключений

| Настройка | Результат |
|-----------|-----------|
| `[]` | Плоский список без групп |
| `[Компания]` | Группы по компаниям, внутри плоско |
| `[Компания, Филиал]` | Компания → Филиал |
| `[Филиал]` | Группы по филиалам |
| `[Филиал, Компания]` | Филиал → Компания |

### Трей

Ограничиваемся первым уровнем группировки. Если `group_by` пустой — все подключения плоско.

## Кейс: домашний роутер

С `group_by = ["company"]`:
```
НИЦ Энерго
  Офис (87.249.5.138)
Gymnasium
  Крылатское, Лапино, Рига...
Дом
  Домашний (192.168.1.1)
```

С `group_by = []`:
```
Офис (87.249.5.138)
Крылатское (77.95.204.158)
...
Домашний (192.168.1.1)
```

Ключевое: пользователь не обязан заполнять оба поля. Можно группировать по одному label, второй оставить пустым.

## Реализация

### 1. Store (backend)

Добавить `group_by: Vec<String>` в `Store`:

```rust
pub struct Store {
    pub connections: Vec<Connection>,
    pub labels: Vec<Label>,
    pub group_by: Vec<String>,  // ordered label IDs
}

impl Default for Store {
    fn default() -> Self {
        Self {
            connections: vec![],
            labels: vec![...],
            group_by: vec!["company".into(), "branch".into()],
        }
    }
}
```

Десериализация совместима: если поле отсутствует в JSON — дефолт `["company", "branch"]`.

### 2. Backend команды

Добавить команду:
- `save_group_config(group_by: Vec<String>)` — сохранить порядок группировки
- `get_group_config() -> Vec<String>` — получить текущий порядок

### 3. Settings UI (frontend)

Новая секция "Группировка":
- Reorderable список выбранных labels
- Dropdown для добавления нового
- Кнопка удаления (✕)
- Preview результатной группировки

### 4. ConnectionList (frontend)

Заменить фиксированную `groupByCompany()` на рекурсивную:

```typescript
function groupRecursive(
  conns: ConnectionWithStatus[],
  groupBy: string[]
): (GroupNode | ConnectionWithStatus)[] {
  if (groupBy.length === 0) return conns;
  const [field, ...rest] = groupBy;

  const groups = new Map<string, ConnectionWithStatus[]>();
  const unlabeled: ConnectionWithStatus[] = [];

  for (const c of conns) {
    const val = c.labels[field];
    if (!val) {
      unlabeled.push(c);
    } else {
      if (!groups.has(val)) groups.set(val, []);
      groups.get(val)!.push(c);
    }
  }

  const grouped: GroupNode[] = [...groups.entries()]
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([name, items]) => ({
      labelId: field,
      name,
      items: groupRecursive(items, rest),
    }));

  // сгруппированные узлы + негруппированные connections напрямую
  return [...grouped, ...unlabeled];
}
```

Тип:
```typescript
type GroupNode = {
  labelId: string;
  name: string;
  items: GroupNode[] | ConnectionWithStatus[];
};
```

Отрисовка рекурсивная: каждый `GroupNode` — строка-заголовок + дочерние элементы.

### 5. Tray (backend)

Аналогичная рекурсивная группировка, но с ограничением в 1 уровень (tray menu неудобно с глубокой вложенностью).

### 6. Миграция

Текущие JSON файлы без `group_by` десериализуются с дефолтом `["company", "branch"]` — ничего не ломается.
