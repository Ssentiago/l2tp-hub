# Архитектура

Документ описывает общее устройство приложения, модель процессов, каналы IPC и потоки
данных между компонентами.

## Обзор

L2TP Hub это десктопное приложение Tauri v2. Оно состоит из фронтенда на React,
бэкенда на Rust и двух привилегированных демонов. Ядро VPN-логики вынесено в
отдельный крейт `l2tp-hub-core`, который не зависит от Tauri.

Встроенный в macOS менеджер L2TP-подключений неудобный и кривой, поэтому написан свой.
Приложение управляет VPN полностью в userspace: туннель строится из bundled strongSwan
(демон charon) и xl2tpd поверх системного pppd. Эти демоны запускаются как
LaunchDaemon'ы под root.

## Компоненты

| Компонент       | Тип                              | Назначение                              |
| --------------- | -------------------------------- | --------------------------------------- |
| Фронтенд `src/` | React, выполняется в webview     | Интерфейс, зовёт команды через invoke   |
| `src-tauri`     | Rust, процесс приложения         | Команды, state, события, жизненный цикл |
| `l2tp-hub-core` | Rust-библиотека                  | Модели, база, ключи, L2TP-логика        |
| helper          | Rust, отдельный процесс под root | Выполняет команды из allowlist от root |
| route-guardian  | Rust, отдельный процесс под root | Мониторит сеть и VPN, делает cleanup    |
| charon          | bundled strongSwan               | IKE и IPSec                             |
| xl2tpd          | bundled, с патчами               | L2TP, поднимает pppd                    |
| pppd            | системный                        | PPP-интерфейсы `pppN`                   |

## Модель процессов

Приложение и его демоны живут в разных процессах с разными привилегиями.

Процесс приложения (пользовательский). Запускает Tauri, хранит состояние в SQLite,
общается с фронтом по IPC Tauri. Root-прав не имеет.

helper (root, постоянный). LaunchDaemon `com.sentiago.l2tp-hub.helper`. Слушает unix
socket `/var/run/l2tp-hub-helper.sock`. Получает от приложения argv в виде JSON-массива,
выполняет команду от root и возвращает результат. Работает всегда, пока установлен.
Debug-сборка helper работает как отдельный dev-helper с сокетом
`/var/run/l2tp-hub-helper-dev.sock` и меткой `com.sentiago.l2tp-hub.dev`.

route-guardian (root, постоянный). LaunchDaemon `com.sentiago.l2tp-hub.guardian`.
Слушает `/tmp/l2tp-hub-guardian.sock`. Мониторит физическую сеть и VPN-процессы.
Получает heartbeat от приложения каждые 3 секунды. Если heartbeat пропадает на 12
секунд и PID приложения мёртв, делает cleanup маршрутов и VPN-процессов.

charon и xl2tpd (root, на время подключения). LaunchDaemon'ы
`com.sentiago.l2tp-hub.charon` и `com.sentiago.l2tp-hub.xl2tpd`. Запускаются при
подключении, останавливаются при отключении. Один экземпляр каждого обслуживает все
активные подключения одновременно.

## Каналы IPC

Фронтенд и бэкенд. Стандартный IPC Tauri. Фронт вызывает команды через `invoke`,
бэкенд эмитит события через `app.emit`. Основные события: `vpn-status-changed`,
`app-shown`, `app:log`.

Приложение и helper. Unix socket `/var/run/l2tp-hub-helper.sock`. Запрос: одна строка
JSON-массива argv, например `["cp", "a", "b"]`. Ответ: одна строка JSON вида
`{"ok": bool, "stdout": string, "stderr": string}`. Права сокета 0660 (root:admin),
каждое подключение проверяется в два шага: peer credentials (разрешены root и
консольный пользователь) и кодовая подпись пира по audit token против файла доверия
с зачисленным cdhash приложения (подробности в `docs/daemons.md`). Команды проходят
allowlist с валидацией аргументов (`helper/src/allowlist.rs`); `version` и
`guardian_start` обрабатываются отдельно, всё остальное выполняется от root только в
разрешённых формах.

Приложение и guardian. Unix socket `/tmp/l2tp-hub-guardian.sock`. Запрос: строка JSON
`{"cmd": "...", ...}`. Ответ: строка JSON `{"ok": bool, ...}` с полями состояния.

Управление демонами. Через helper командами `launchctl bootstrap`, `launchctl
kickstart`, `launchctl kill`, `launchctl bootout`.

## Инициализация приложения

Порядок запуска в `src-tauri/src/main.rs`:

1. `fix_path_env::fix()` восстанавливает `$PATH` для GUI-приложения.
2. `state::cleanup_all_vpn_state()` убивает осиротевшие VPN-процессы прошлого запуска.
3. Создаётся логгер, инициализируется `AppEnv` с путями приложения.
4. Открывается SQLite пул и поднимается актор состояния, при пустой базе выполняется
   миграция из старого JSON.
5. В managed state кладутся `SudoSession` и `L2tpManager`.
6. Регистрируется глобальный шорткат показа окна.
7. Подписка на события сна и пробуждения через IOKit.
8. Регистрируются 33 команды и плагины dialog, fs, global-shortcut.

## Поток данных при подключении

Краткая схема того, что происходит при нажатии "подключить". Подробно в
`vpn-lifecycle.md`.

1. Фронт зовёт команду `connect_vpn`.
2. `L2tpManager::connect` проверяет правила режимов и пересечение подсетей.
3. Из связки ключей читаются пароль и общий ключ.
4. Генерируются конфиги swanctl, xl2tpd, pppd, strongswan.
5. Конфиги деплоятся в root-директорию активного состояния.
6. Запускаются charon и xl2tpd как LaunchDaemon'ы.
7. `swanctl --load-all` загружает IPSec конфигурацию.
8. pppd поднимает интерфейсы `pppN`, выставляются маршруты.
9. Стартует guardian и heartbeat-поток.
10. Бэкенд эмитит `vpn-status-changed` со статусом.

## Разделение по платформам

macOS. Основная платформа. Полная функциональность: helper, guardian, LaunchDaemon'ы,
split tunneling, переподключение после сна.

Windows. Упрощённая поддержка. Привилегированный запуск идёт напрямую через манифест
`requireAdministrator`, helper и guardian не используются, split tunneling не
поддерживается. VPN-логика для Windows находится в `l2tp-hub-core/src/l2tp/windows`.

Условная компиляция. В ядре модули разделены через `#[cfg(target_os = ...)]`.
Публичные функции `l2tp` реэкспортируют платформенную реализацию, поэтому вызывающий
код не различает платформы.

## Пути и состояние

Приложение держит данные в нескольких местах. Пользовательская база и конфиги в
директории данных приложения, привилегированное активное состояние в
`/private/var/root/l2tp-hub/active`, логи во `/tmp/l2tp`, состояние маршрутов в
`/private/var/root/l2tp-hub/route.state`. Полный список путей и назначение файлов
приведён в `vpn-lifecycle.md` и `daemons.md`.
