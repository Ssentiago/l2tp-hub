# Tauri-слой (src-tauri)

Документ описывает бэкенд приложения на Tauri v2: структуру, managed state, полный
список команд, события, обработку сна и выхода.

## Структура

Модули в `src-tauri/src`:

| Модуль | Назначение |
|--------|-----------|
| `main.rs` | Точка входа, сборка приложения, регистрация команд, выход |
| `commands/` | Реализация Tauri-команд, разбита по доменам |
| `sudo.rs` | `SudoSession`, авторизация и запуск через helper |
| `helper.rs` | Клиент unix-сокета helper |
| `sleep_wake.rs` | Подписка на сон и пробуждение через IOKit |
| `state.rs` | Глобальное состояние приложения, очистка VPN |
| `backup.rs` | Шифрованный экспорт и импорт конфигурации |
| `logger.rs` | Логгер, пишет в файл и эмитит событие `app:log` |
| `startup/` | Почти мёртвый модуль, содержит `show_alert` без вызовов |

Плагины: dialog, fs, global-shortcut. Обновления реализованы вручную в
`commands/update.rs`, плагин updater не используется.

## Managed state

В Tauri регистрируются два объекта состояния:

`SudoSession`. Отвечает за привилегированный запуск через helper. Хранит флаг
авторизации и текст статуса для UI.

`L2tpManager`. Централизованный менеджер VPN-подключений из ядра. Создаётся с
`Arc<dyn PrivilegedExecutor>` (на базе `SudoSession`), `AppEnv` и хэндлом актора
состояния (`StoreHandle`), через который идут все мутации store.

## Точка входа

`main()` выполняет следующее: чинит `$PATH`, чистит осиротевшие VPN-процессы,
собирает приложение с плагинами single-instance (второй запуск поднимает уже
работающее окно) и global-shortcut, перехватывает закрытие окна (кнопка
прячет окно, а не завершает приложение), в setup создаёт логгер, открывает базу,
поднимает актор состояния, кладёт state, регистрирует шорткат `Ctrl+Alt+L` и
подписку на сон и пробуждение. Затем регистрирует команды и плагины.

## События

Бэкенд эмитит события через `app.emit`:

`vpn-status-changed`. Полезная нагрузка `{ id, status, connected_since, error }`.
Отправляется при изменении состояния туннеля. При мульти-подключении после старта или
остановки xl2tpd статус переотправляется для всех активных подключений, потому что
PPP-интерфейсы пересоздаются.

`app-shown`. Пустая полезная нагрузка. Отправляется при показе окна через шорткат,
фронт сбрасывает поиск и режим просмотра.

`app:log`. Полезная нагрузка `{ message, timestamp }`. Каждая строка лога уходит во
фронт для консоли отладки.

## Авторизация через helper

`SudoSession` в `sudo.rs` управляет привилегированным сервисом. `authenticate()`
выполняет трёхшаговую эскалацию: если helper работает, проверяет версию; если
установлен но не работает, запускает через launchctl; если не установлен, ставит через
`osascript` с правами администратора.

Рукопожатие версий. Приложение сравнивает версию helper (`version` команда) с
`EXPECTED_VERSION` из `src-tauri/Cargo.toml`. Версии helper и приложения поднимаются
вместе через `jrit`, поэтому при несовпадении helper переустанавливается при
обновлении приложения (заодно перезаписывается файл доверия с cdhash нового билда), а
не при каждом запуске. Рассинхрон версий описан в `AGENTS.md`.

`run_sudo(args)` шлёт argv в helper и возвращает stdout. Это реализация трака
`PrivilegedExecutor`, через которую ядро выполняет root-команды.

## Сон и пробуждение

`sleep_wake.rs` подписывается на уведомления питания IOKit через FFI. При засыпании
только логируется событие. При пробуждении выполняется переподключение: выдержка 3
секунды на подъём сети, затем для каждого активного подключения проверяется живость
IPSec SA, и мёртвые переподключаются. Логика дебаунса через `AtomicBool` в `main.rs`.

Мост в async. Колбэки IOKit и обработчик выхода работают вне tokio-воркера, поэтому
создают отдельный `tokio::runtime::Runtime`. Не вызывайте `Handle::block_on` или
`Runtime::new` изнутри tokio-воркера, это паникует.

## Выход из приложения

Обработчик `RunEvent::Exit` для каждого активного подключения создаёт свежий runtime,
оборачивает отключение в `catch_unwind` и логирует результат. Затем вызывается
`cleanup_all_vpn_state` для убийства всех VPN-процессов. Кнопка закрытия окна не
завершает приложение, а прячет его.

## Шифрование конфигурации

`backup.rs` реализует экспорт и импорт. Формат и вывод ключа описаны в
`data-model.md`. Криптография: AES-256-GCM, случайный nonce, ключ выводится из
пароля через Argon2id со случайной солью. Старые бэкапы версии 1 читаются как есть.
