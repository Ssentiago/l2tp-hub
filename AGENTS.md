# L2TP Hub — AGENTS.md

Этот файл описывает устройство проекта, чтобы разработчик или AI-агент мог быстро
разобраться в коде и ничего не сломал. Здесь собрана архитектура, роли крейтов,
конвенции и опасные места. Детальная документация по подсистемам лежит в `docs/`.

## Что это

Настольное приложение (macOS и Windows) для управления несколькими L2TP/IPSec VPN
подключениями. Заточено под администраторов, которые держат много клиентских сетей.

Зачем это нужно: встроенный в macOS менеджер L2TP-подключений неудобный и кривой для
работы с множеством сетей. Это приложение заменяет его нормальным менеджером. Туннель
собирается в userspace из bundled strongSwan (`charon`) и `xl2tpd` поверх системного
`pppd`, приложение управляет этими демонами через LaunchDaemon'ы и привилегированные
хелперы.

Функции: быстрое подключение, метки и рабочие пространства, фильтрация и сортировка,
экспорт и импорт конфигурации с шифрованием AES-256-GCM, хранение паролей в системной
связке ключей, split и full туннелирование, переподключение после сна.

## Структура репозитория

Проект монорепо из четырёх Rust-крейтов и одного фронтенда.

| Путь                | Что это                                                              |
| ------------------- | -------------------------------------------------------------------- |
| `l2tp-hub-core/`    | Ядро на Rust, независимое от Tauri. Модели, база, ключи, L2TP-логика |
| `src-tauri/`        | Приложение Tauri v2. Команды, состояние, sudo, sleep/wake            |
| `helper/`           | Привилегированный хелпер-демон с root-доступом                       |
| `route-guardian/`   | Демон-сторож маршрутов и VPN-процессов                               |
| `src/`              | Фронтенд на React 19 + TypeScript + Zustand + MUI                    |
| `build-strongswan/` | Скрипты и патчи сборки нативных зависимостей                         |
| `docs/`             | Подробная документация по подсистемам                                |

Вспомогательные файлы в корне: `build.sh` (сборка нативных зависимостей),
`jrit.toml` (автоматизация релизов и версий), `ike-sa-init-payload.bin` (захваченный
IKE-пакет для проверки сервера), `CHANGELOG.md`.

## Крейты и их роли

`l2tp-hub-core` (версия 0.1.0). Библиотека без Tauri. Публичные модули: `db`
(SQLite), `env` (пути приложения), `executor` (трак привилегированного запуска),
`guardian` (клиент сокета guardian), `keychain` (связка ключей), `l2tp` (вся
VPN-логика по ОС), `models` (структуры данных), `store` (загрузка и сохранение
состояния), `utils` (хеш сервиса).

`src-tauri` (пакет `l2tp-hub`, версия 1.0.0, edition 2024). Tauri-обёртка. Держит
managed state, регистрирует команды, эмитит события, управляет выходом и сном.
Зависит от `l2tp-hub-core` по пути.

`helper` (пакет `l2tp-hub-helper`, версия 0.8.0). Демон с root-правами, слушает unix
socket `/var/run/l2tp-hub-helper.sock`. Выполняет команды от имени root. Зависимости:
serde, serde_json, libc (для проверки peer и umask), security-framework и
core-foundation (проверка кодовой подписи пира, только релизная сборка). Debug-сборка
работает как отдельный dev-helper: сокет `/var/run/l2tp-hub-helper-dev.sock`, метка
`com.sentiago.l2tp-hub.dev`, проверка подписи не компилируется.

`route-guardian` (пакет `l2tp-hub-guardian`, версия 0.8.0). Демон с root-правами,
слушает `/tmp/l2tp-hub-guardian.sock`. Мониторит VPN и физическую сеть, делает
cleanup при пропаже heartbeat или смерти Tauri.

## Сборка и запуск

Пакетные скрипты (см. `package.json`):

| Команда                  | Что делает                                                             |
| ------------------------ | ---------------------------------------------------------------------- |
| `npm run tauri:dev`      | Запуск в режиме разработки                                             |
| `npm run tauri:build`    | Продакшн-сборка приложения                                             |
| `npm run build:helper`   | Собирает helper, кладёт бинарь и plist в `src-tauri/resources/helper/`   |
| `npm run build:helper:dev` | Собирает dev-helper (debug) в `helper/target/debug`, в ресурсы не кладёт |
| `npm run build:guardian` | Собирает guardian, кладёт в `src-tauri/resources/guardian/`            |
| `npm run build:deps`     | Собирает нативные зависимости (strongSwan, xl2tpd, OpenSSL)            |
| `npm run build:all`      | helper + guardian + зависимости + tsc + vite + tauri                   |

Порядок полной сборки: сначала `build:helper` и `build:guardian`, затем `build:deps`
(или `--skip-ssl` для переиспользования OpenSSL), затем фронт и Tauri. Нативные
бинарники должны лежать в `src-tauri/resources/` до `tauri build`, иначе они не
попадут в бандл.

Требования: macOS 13+ или Windows 10/11, Xcode Command Line Tools, bun или npm.

## Как устроен процесс

Приложение поднимает цепочку демонов только на время подключения (charon и xl2tpd)
и два постоянных привилегированных сервиса (helper и guardian).

1. Приложение стартует, чинит `$PATH` через `fix-path-env`, убивает осиротевшие
   VPN-процессы прошлого запуска, инициализирует `AppEnv` и SQLite пул.
2. `SudoSession` в managed state проверяет helper: запущен ли, совпадает ли версия.
   При необходимости helper ставится через `osascript` с правами администратора.
3. При подключении генерируются конфиги, charon и xl2tpd запускаются как LaunchDaemon,
   выставляются маршруты, стартует guardian и heartbeat-поток.
4. Статус туннеля эмитится во фронт событием `vpn-status-changed`.
5. При выходе из приложения активные подключения отключаются, VPN-процессы убиваются.

Детали модели процессов и IPC: `docs/architecture.md` и `docs/daemons.md`.

## Важные конвенции

Асинхронность. `store::load` и `store::save` это `async fn`. Все вызовы через `.await`.
Синхронные обёртки над async-кодом через `tauri::async_runtime::block_on` из async
контекста запрещены: это падает с "Cannot start a runtime from within a runtime".
Вне tokio-воркера (IOKit callback, main thread при выходе) создаётся отдельный
`tokio::runtime::Runtime`. Внутри tokio-воркера допустим только
`tokio::task::block_in_place` вокруг `Handle::block_on`.

Мьютексы. Везде используется восстановление от poisoning:
`lock().unwrap_or_else(|p| p.into_inner())`, а не `lock().unwrap()`.

Привилегии. Ядро не вызывает root напрямую. Оно получает `&dyn PrivilegedExecutor`
и просит выполнить команду. В GUI этим занимается `SudoSession`, который шлёт argv
в helper по unix socket. В ядро не добавляются прямые `sudo` вызовы.

Именование. Поле `Connection.service_name` в коде раньше называлось `name`. В JSON
остался алиас `#[serde(alias = "name")]`. В бэкенде используется `service_name`.

Секреты. Пароли и общие ключи не хранятся в базе. В базе лежат только ключи
`password_{id}` и `shared_{id}`, сами значения в системной связке ключей (сервис
`com.sentiago.l2tp-hub`). Пустые поля пароля при сохранении означают "оставить как есть".

Мульти-подключения. Один charon и один xl2tpd обслуживают несколько LAC-секций.
Порядок `all_conns` детерминирован (существующие по id, новое в конце), от него
зависит назначение `pppN` через `unit {idx}`. Этот порядок не должен меняться.

## Документация и код

Главнее код. В споре между документацией и кодом истина всегда на стороне кода.
Документация это не спецификация, а описание того, что уже работает. Если она
расходится с кодом, верен код, а документация считается устаревшей.

После любого изменения кода документация актуализируется под код, а не наоборот.
В доках описывается то, что есть, а не то, что "должно быть". При правке логики,
структуры, команд или путей сразу обновляются `AGENTS.md`, файлы в `docs/` и
комментарии в коде, которые это описывают. Устаревшее описание хуже его
отсутствия, оно вводит в заблуждение следующего, кто откроет проект.

## Опасные места

Версии helper. `helper/Cargo.toml` сейчас 0.8.0, а приложение ждёт версию из
`src-tauri/Cargo.toml` (1.0.0). При несовпадении `authenticate()` переустанавливает
helper. При изменении протокола helper его версия поднимается осознанно.

Сокет helper защищён: права 0660 root:admin, проверка пира через getpeereid (разрешены
root и консольный пользователь), allowlist команд с валидацией аргументов в
`helper/src/allowlist.rs`. Релизная сборка дополнительно проверяет кодовую подпись
пира: audit token через `getsockopt LOCAL_PEERTOKEN`, затем `SecCodeCheckValidity` по
требованию из `/Library/PrivilegedHelperTools/l2tp-hub-helper.trust` (зачисленный
cdhash приложения, файл пишет root при установке helper). Приложение подписано
ad-hoc (`signingIdentity: "-"` в tauri.conf.json), поэтому обновление приложения
меняет cdhash и зачисляет его через переустановку helper; dev-сборки идут через
отдельный dev-helper без проверки подписи. Остаточный риск: любой, кто может
переустановить helper (пароль администратора), зачисляет произвольный бинарь.
Allowlist повторяет формы команд из ядра: при изменении вызовов в `l2tp-hub-core`
его нужно синхронно править, иначе helper начнёт отклонять команды приложения. Сокет
route-guardian (`/tmp/l2tp-hub-guardian.sock`) остаётся 0777 без проверки пира, это
отдельная неустранённая дыра.

Маршрутизация. Полный туннель перехватывает default route. При сбое проверки ping
маршрут откатывается. Состояние маршрутов пишется в
`/private/var/root/l2tp-hub/route.state` для восстановления после падения. Изменение
маршрутной логики требует понимания `l2tp-hub-core/src/l2tp/macos/routes.rs`.

Dead code. Часть фронтовых файлов не используется в активном коде: `src/pages/About`,
`src/pages/ConnectionForm`, файлы `*.bak`. Модуль `src-tauri/src/startup` почти
мёртвый. Скрипт `resources/route-guardian.sh` вытеснен демоном `route-guardian`.
Рабочими точками входа они не являются.

## Чего не делать

Автоматические форматеры и массовый рефакторинг не запускаются. Чужой код стилистически
не переписывается без задачи. Документация и md-файлы, описывающие изменённый код,
коммитятся вместе с этим кодом в одном коммите. В репозиторий не попадают только явно
мусорные и временные md-файлы: личные планы, черновики и заметки. Изменения проверяются
по факту компиляции и запуска, а не по виду дифа.
